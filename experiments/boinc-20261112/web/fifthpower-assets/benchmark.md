# Physical M4 BOINC CPU / Metal comparison — 2026-11-13

The Metal application was **2.23× faster in application elapsed time** than the
single-thread CPU application on this M4. Including BOINC startup and wrapper
costs, the observed speedup was **1.24×**. All six results became canonical after
fresh independent GMP validation. These are TEST_ONLY replays, not production
search coverage.

## Matched sample and method

Each task replayed the same immutable 42-packet manifest: **789,435,567 candidate
coefficient positions**, comprising 23 realistic packets (775,687,194 positions),
16 small packets (13,748,364), and three known-hit controls (nine positions).
There were three CPU/GPU pairs, in CPU1/GPU1/CPU2/GPU2/CPU3/GPU3 order. The
controller submitted the next task only after the preceding one was validated,
so the two benchmark applications did not overlap. Overall replay count across
six tasks was **4,736,613,402 positions**, with zero new scientific coverage.

The Mac reported Apple M4, 10 CPU cores, 16 GiB RAM, Darwin 25.6.0 and BOINC
8.2.11; the owner identifies it as Tahoe 26.6.2. This compares **one native CPU
engine thread with the integrated Apple GPU**, not all ten CPU cores. Native
packages were already cached from the earlier accepted controls. Every task
started with no resumed packet prefix. Each GPU task also passed its 1,100-case
exact arithmetic self-test and recorded BOINC device 0 and the Apple M4 Metal
registry identity.

## Results

All times below are seconds. Application elapsed includes the persistent engine,
packet RPC/verification and durable per-packet files. It excludes the launcher's
GPU allocation probe and arithmetic self-test. BOINC elapsed includes task-slot
startup, runtime ZIP extraction, bundled Python, launcher checks and wrapper
completion. Transfer/reporting waits and server-side GMP checking are outside
both Mac elapsed measures.

Median sum of packet engine times was 1.795259 CPU seconds and
0.773793 GPU seconds (2.32×).
Packet RPC sums were 1.800601 and 0.781112 seconds.
Application throughput was approximately 375.2 million candidate
positions/s on CPU and 835.0 million on GPU. These are coefficient
positions replayed by the current sieve, not newly covered integers or counts
of full fifth-power evaluations.

The three runs per backend are short. Background load, CPU core placement,
thermal state and power were not instrumented. This establishes an observed
speed advantage for the current sample; it is not a sustained-performance or
energy-efficiency result. GPU interruption/checkpoint recovery and other Mac
models remain separate validation work.

## Exact orchestration and resources

The executed controller is the versioned
[`stock/macos/benchmark/run.py`](../stock/macos/benchmark/run.py), via a private
copy `recipe/mac-benchmark.py`. The full manifest was generated by the existing
`make_manifest.py` using all 42 catalog names; the exact argument vector is
`evidence/mac-benchmark/manifest-command.json`. The first submitted workunit was
`mac_m4_bench_cpu_01_20261113`; later names follow
`mac_m4_bench_{cpu,gpu}_{01,02,03}_20261113`. CPU tasks bind app-version ID 1
and the trusted CPU engine; GPU tasks bind ID 3, backend gpu and the trusted
Metal engine. All command vectors and submission output are in that evidence
directory. Existing immutable workunit names must not be resubmitted.

The controller entered only the existing Mac namespace using the following
historical invocation on Cabbage (these job names already exist):

```bash
mac_anchor=$(pgrep -f '^python3 /recipe/mac-server-wait.py$')
systemd-run --user --unit=fifth42-boinc-mac-benchmark-20261113 \
  --collect --service-type=exec -p CPUQuota=50% -p MemoryMax=512M \
  -p MemorySwapMax=0 -p TasksMax=32 -p Nice=19 -p RuntimeMaxSec=30min \
  nsenter --target "$mac_anchor" --user --mount --net --pid \
  --preserve-credentials bash -c '
export HERE=/source/experiments/boinc-20261112 STOCK=/pilot/mac-server
export RUNTIME=/pilot/science/runtime
source "$STOCK/env.sh"
exec python3 /recipe/mac-benchmark.py'
```

It completed in 737.213 seconds including the initial wait for the owner's
Update, client reporting and GMP validation; the user unit recorded 5.024 CPU
seconds and 152.2 MiB peak memory. The temporary RPC helper used 25% CPU,
128 MiB/no swap/16 tasks and a 31-minute maximum. It requested 20-second project
check-ins and removed that setting after completion; restoration is recorded.
Both benchmark helper units stopped. The owner can restore BOINC CPU and GPU
Activity settings to their normal preferences.
